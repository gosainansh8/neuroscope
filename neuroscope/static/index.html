            Frequently asked

            Questions, answered.

            Where does the information come from?

            ClinicalTrials.gov for trials, the FDA's Drugs@FDA database and drug labels for approvals, and PubMed for published abstracts. All three refresh automatically every Monday.

            How does it avoid making things up?

            The language model never sees the database directly: it can only request a few read-only lookups and must answer from what they return. Code, not the model, then checks that every trial ID, FDA application number, and PubMed ID in the answer came from one of those lookups.

            Does "FDA-approved" mean approved for Alzheimer's disease?

            Not necessarily. It means approved for at least one use; semaglutide, for example, is approved for diabetes, not Alzheimer's. Whether a use includes Alzheimer's comes only from the drug's label, which answers quote.

            What does "no matched FDA approval record" mean?

            No FDA approval matched the drug's name. That usually means it is not approved, but it is not proof, since only exact names and US FDA data are used. Approval is never inferred from a drug reaching Phase 3 or 4.

            Can I trust every answer?

            Treat answers as a well-sourced starting point. The check confirms each cited record is real, not that it supports the exact sentence, so follow the links for anything important.

            Why is there a daily question limit?

            Each new question costs a language-model call, so the demo answers up to 50 new questions a day. Recently asked questions come from saved answers and don't count.

            Is this medical advice?

            No. It summarizes public research and regulatory records and does not recommend treatments. Talk to a doctor about medical decisions.

            How was it built?

            Python and Postgres with vector search, Gemini on Google Cloud for answers and embeddings, and Cloud Run for hosting. The code is on GitHub.
